Project Overview & Objectives

The Blood Bank Management System is a full-stack web application that digitises and streamlines blood bank operations. It brings together three types of users — Admins, Donors, and Requesters — on a single platform, enabling real-time blood inventory management, donation tracking, blood request processing, and public donor search.

This project was built as a college project to demonstrate practical knowledge of web development, database design, user authentication, and secure coding practices using the Django framework.

What the System Does

  • Provides a centralised platform for managing blood donations and requests
  • Tracks blood stock in real-time — automatically updates when donations are made or requests are approved
  • Allows patients to submit blood requests with urgency levels: Normal, Urgent, or Emergency
  • Lets admins approve or reject requests and manage donor health eligibility
  • Offers a public donor search — filter by blood group, city, or pincode
  • Sends in-app notifications for all key events (approvals, rejections, donations)
  • Exports donor and request data to CSV for reporting
  • Provides a secure, question-based password reset — no email or SMS required

Smart Stock Management (Automatic)

Two models have custom save() overrides that keep blood stock accurate automatically:

  • Donation.save() — when a donation is recorded, the matching BloodStock units are automatically increased
  • BloodRequest.save() — when a request is approved, stock is checked. If enough units exist, stock is reduced. If not, the request is automatically rejected

Module 1 — User Authentication & Registration

  • Custom User model extending Django's AbstractUser with a role field and unique email
  • Login accepts phone number (username) OR full name — case-insensitive with whitespace normalisation
  • Registration collects full profile: name, email, phone, blood group, age, gender, weight, health details, and location
  • Duplicate prevention: unique email at DB level, unique phone, case-insensitive full name check
  • Strong password rules at registration only: min 8 chars, uppercase, lowercase, digit, special character
  • Live password strength indicator (5 levels: Very Weak → Strong) with real-time checklist
  • Confirm password field with live match indicator
  • Role-based dashboard routing after login
  • Secure logout via POST form — prevents CSRF-based forced logout
  • Editable user profile page for name, email, and location

Module 2 — Security Question Password Reset

  • 3-step flow: Enter phone/email → Answer security question → Set new password
  • 8 predefined security questions — user picks one at registration
  • Answers stored as PBKDF2 hashes — never stored in plain text
  • Answers are case-insensitive (normalised to lowercase before hashing)
  • Brute-force protection: 3 wrong answers triggers a 15-minute account lockout
  • All reset attempts are logged to bloodbank.log
  • New password validated against Django's full password validators before saving
  • Session-gated: users cannot skip steps or jump directly to the reset page

Module 3 — Blood Inventory Management

  • Admin adds blood groups (A+, A-, B+, B-, O+, O-, AB+, AB-) and stock units
  • Stock automatically increases when a donation is recorded
  • Stock automatically decreases when a blood request is approved
  • If stock is insufficient at approval time, the request is automatically rejected
  • Public blood availability page — no login required to view

Module 4 — Blood Donations

  • Donors log their blood donations with units donated
  • 90-day cooldown enforced — system shows exact days remaining before next donation
  • Eligibility check before donation — PENDING and REJECTED donors cannot donate
  • Donor availability is set to Offline after donation for the recovery period
  • In-app notification created automatically after each donation
  • Full donation history page showing date and units for each donation

Module 5 — Blood Requests

  • Any authenticated user can submit a blood request
  • Three urgency levels: Normal, Urgent, Emergency (colour-coded in admin view)
  • Admin approves or rejects with an optional rejection reason
  • Approval auto-deducts stock; auto-rejects if stock is insufficient
  • Requester receives an in-app notification on every status change
  • My Requests page shows status, urgency level, and rejection reason
  • CSV export of all requests available to admin

Module 6 — Public Donor Search

  • Publicly accessible — no login required to search for donors
  • Filter by blood group, city, and pincode
  • Only shows donors who are available and eligible
  • Phone number is hidden from unauthenticated visitors

Module 7 — In-App Notifications

  • 4 notification types: info, success, warning, danger
  • Unread count shown as a badge on the navbar bell icon (via context processor)
  • Mark individual notifications as read, or mark all as read at once
  • Notifications auto-created for: donation recorded, request approved/rejected, health status approved/rejected

Module 8 — Service Ratings

  • Requesters can rate an approved blood request after it is fulfilled
  • Two separate ratings: Donor Experience (1–5 stars) and Service Rating (1–5 stars)
  • Optional text feedback field
  • One rating per request — prevents duplicate ratings
  • Rating status shown in the My Requests page

Security Features
Security FeatureHow It Works
CSRF Protection Every POST form includes a CSRF token. Logout uses a POST form to prevent forced-logout attacks via malicious links.
Password Hashing Django's PBKDF2-SHA256 algorithm via create_user() and set_password(). Passwords are never stored in plain text.
Strong Password Rules Applied at registration only: minimum 8 characters, must include uppercase, lowercase, digit, and special character. Does not affect login or password reset.
Security Answer Hashing Security question answers are hashed with PBKDF2 via Django's make_password(). Answers are normalised to lowercase before hashing for case-insensitive comparison.
Brute-Force Protection 3 wrong security question answers triggers a 15-minute account lockout. The lockout timestamp is stored in SecurityProfile.locked_until.
Unique Data Constraints Email is unique at the database level (unique=True) and checked in the view. Phone number (username) is unique. Full name is checked case-insensitively before saving.
Role-Based Access Control Views check request.user.role and request.user.is_staff. Non-donors are redirected away from donation views. Non-staff are redirected away from admin views.
Session-Gated Password Reset The 3-step reset flow uses Django session keys. Users cannot skip steps or access the reset page directly without completing the prior steps.
Login Required Decorator All authenticated views use @login_required. Unauthenticated users are redirected to the login page automatically.
Clickjacking Protection XFrameOptionsMiddleware adds the X-Frame-Options: DENY header to all responses.
Application Logging Auth events, password reset attempts, and wrong answer attempts are logged to both the console and bloodbank.log.
Input Normalisation Email is lowercased before saving. Phone numbers are stripped of whitespace. Full names are trimmed. Security answers are lowercased before hashing.

External APIs & Third-Party Services

Pincode Auto-Fill (Registration Page)

When a user types their 6-digit pincode during registration, the system automatically fetches and fills in the city, state, and country. This is done entirely client-side using JavaScript fetch() with a 400ms debounce to avoid excessive API calls.

APIEndpointRoleCost
PostalPincode.in api.postalpincode.in/pincode/{pin} Primary source — fetches city, state, country from Indian pincode Free, no API key needed
Nominatim (OpenStreetMap) nominatim.openstreetmap.org/search Fallback — used if the primary API fails or returns no data Free, no API key needed
If both APIs fail, the city, state, and nation fields automatically unlock so the user can type their location manually. The form never gets stuck.

Frontend & UI Design

Design System

The UI is built on Bootstrap 5 with a custom design system using CSS custom properties (variables). The primary colour is Blood Red (#dc2626), chosen to reflect the domain. All colours, backgrounds, and borders switch automatically between light and dark mode.

Dark Mode

Full dark mode is implemented by toggling data-theme="dark" on the HTML element. The user's preference is saved to localStorage and restored on every page load. Comprehensive CSS overrides ensure Bootstrap utility classes like bg-light and text-dark also respect the theme.

Key UI Components

  • Sticky Navbar — notification bell with unread badge, user dropdown, dark mode toggle, responsive hamburger menu
  • Dashboard Cards — clickable navigation cards with icon wrappers and hover lift animation
  • Premium Cards — consistent card style with border, shadow, and hover effects across all pages
  • Floating Emergency Button — fixed bottom-right button for quick blood request access on every page
  • Password Strength Bar — 5-level colour-coded bar (Very Weak → Strong) with live checklist
  • Pincode Auto-fill — live fetch with spinner, success/error states, and manual fallback
  • Star Rating UI — CSS-only interactive stars using radio inputs and reverse flexbox
  • Data Tables — styled tables with alternating rows, badge status indicators, and action buttons
